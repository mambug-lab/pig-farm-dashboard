## 1. Executive Summary

현재 정본은 Apps Script v11.0과 GitHub Pages 대시보드 `index.html`이다. v11.0은 이전의 39행 고정 간격을 제거하고, 날짜 블록 안에서 A열 앵커를 찾은 뒤 같은 행의 E:H 직접입력으로 유효 작업일을 판정한다. 현재 월간연동용의 `유효성 판정: A열 앵커 + E:H 직접입력` 및 KPI 메타는 이 구조와 일치한다.

이번 감사에서 확실히 삭제 가능한 운영 코드는 발견하지 못했다. 코드 내부 참조가 하나뿐인 Apps Script 함수는 메뉴·수동 실행·설치형 트리거의 외부 진입점일 수 있으므로 dead code로 분류하지 않았다. 대시보드의 선언 함수와 주요 DOM ID도 모두 현재 참조가 확인된다.

주요 개선 후보는 다음 세 가지다.

1. 전체 갱신에서 월별 원본을 중복 전수 스캔한다.
2. 이미 수집한 날짜행 목록이 있는데도 각 날짜 블록마다 다음 날짜행을 다시 검색한다.
3. 연간연동용의 넓은 K:R 영역을 매번 전체 초기화한다.

| 등급 | 건수 | 결론 |
| --- | ---: | --- |
| A. 확실히 삭제 가능 | 0 | 확인하지 못함 |
| B. 통합 가능 | 1 | 월간/연간 MSY 메타 행 생성 |
| C. 성능 개선 대상 | 6 | 중복 스캔·재탐색·재읽기·과도 초기화·반복 쓰기·중간 배열 |
| D. 추가 검증 필요 | 3 | 이중 트리거, L3 별도 요청, 고정 최대 조회 범위 |
| E. 유지 필요 | 3 | 메뉴/진단, 계층별 KPI 역할 분리, 화면 상태 |
| F. 구조적 개선 후보 | 1 | 이벤트 처리 방식 통일 |

## 2. Apps Script Audit

### AS-01 — 전체 갱신의 원본 월별 시트 중복 전수 스캔

- 파일/위치: `apps-script/Code.gs` 234~274, 349~463, 470~624, 631~696, 706~737, 1774~1876
- 분류: C. 성능 개선 대상
- 현재 역할: 유효일/KPI/MSY 수집, 최신 월 복사, 연간 원본 연결을 수행한다.
- 문제 이유: `refreshDashboardLinks()`가 `collectAnnualDailyKpiRecords_()`에서 모든 원본 월을 분석한다. 이후 월간 갱신의 `findLatestMonthlySheetWithValidData_()`가 다시 분석하고, 연간 갱신도 각 월을 다시 `analyzeMonthlySheet_()`로 분석한다.
- 중복/의존: `analyzeMonthlySheet_()`의 `scan`, `validBlocks`, `latestDate`, `copyEndRow`는 세 경로 모두에서 같은 입력으로 계산된다.
- 변경 영향: 분석 결과의 공유 범위를 실행 1회로 제한하지 않으면 입력 직후 값 갱신을 놓칠 위험이 있다.
- 권장 조치: 전체 갱신용 `monthlyAnalysisMap`을 한 번 작성하고 KPI 수집·최신 월 선택·연간 복사에 전달한다. 월간/연간 단독 갱신도 공통 분석 컨텍스트를 한 번만 만들도록 한다.
- 판단 확신도: 높음

### AS-02 — 날짜 블록마다 다음 날짜행 재검색

- 파일/위치: `apps-script/Code.gs` `analyzeMonthlySheet_()` 754~954, `collectDateRowsForMonth_()` 1022~1123, `findNextDateRowAfter_()` 1555~1588
- 분류: C. 성능 개선 대상
- 현재 역할: 각 날짜행부터 다음 날짜행 직전까지를 작업일 블록으로 정의한다.
- 문제 이유: `collectDateRowsForMonth_()`가 이미 월의 날짜행 전체를 날짜순으로 반환한 뒤, 반복문 안에서 다시 `findNextDateRowAfter_()`로 이후 행을 탐색한다. 다음 날짜행은 원칙적으로 `dateRows[i + 1]`로 바로 알 수 있다.
- 중복/의존: A열 앵커 검사와 E:H 입력 판정에는 다음 블록 시작 행만 필요하다.
- 변경 영향: 날짜행 중복 처리 규칙(동일 날짜는 최초 행 사용)을 보존해야 한다.
- 권장 조치: `nextDateRow = dateRows[i + 1]?.row || null`을 사용하고, 실제 월별 결과의 날짜 블록 시작/끝 목록이 기존 진단 로그와 같은지 대조한다.
- 판단 확신도: 높음

### AS-03 — 분석 결과가 있는데 복사용 원본 값을 다시 읽음

- 파일/위치: `apps-script/Code.gs` 413~425, 542~563, 706~737, 3923~3951
- 분류: C. 성능 개선 대상
- 현재 역할: 최신 월 및 각 유효 월의 A:I 데이터를 연동 탭에 복사한다.
- 문제 이유: `analyzeMonthlySheet_()`가 `scan.values`로 이미 A:I 값을 보유하지만, `readMonthValuesUntilRow_()`가 같은 원본 범위를 다시 `getValues()`한다.
- 중복/의존: AS-01의 분석 결과 공유와 함께 해결할 수 있다.
- 변경 영향: 현재 `getValues()`의 값 형식과 `scan.values.slice(0, copyEndRow)`의 행·열 구조가 같아야 한다.
- 권장 조치: 공통 분석 객체의 `scan.values`를 복사용으로 재사용하고, 기존 출력과 새 출력의 A:I 값 및 행 수를 비교한다.
- 판단 확신도: 높음

### AS-04 — 연간연동용 K:R 전체 영역 초기화

- 파일/위치: `apps-script/Code.gs` 470~513, `clearMetadataArea_()` 4006~4027
- 분류: C. 성능 개선 대상
- 현재 역할: 이전 KPI/월별 요약의 잔존값을 제거한다.
- 문제 이유: 현재 연간연동용 그리드는 22,796행×26열이며, 매 갱신 때 K:R 전체(약 182,368셀)를 `clearContent()`한다. 대시보드가 읽는 연간 메타·월별 요약은 상단 K1:O30이다.
- 중복/의존: 이전 연도 또는 이전 집계의 잔존 행 제거 목적은 유효하다.
- 변경 영향: 임의로 범위를 축소하면 기존 월별 집계 행이 남을 수 있다.
- 권장 조치: 기존/신규 월별 요약의 마지막 사용행 중 큰 값까지만 초기화하거나, 관리 대상 영역의 상한을 명시한다. 잔존 행 회귀 테스트가 선행되어야 한다.
- 판단 확신도: 높음

### AS-05 — 헤더의 셀 단위 반복 쓰기

- 파일/위치: `apps-script/Code.gs` `writeMonthlyHeader_()` 3058~3197, `writeAnnualHeader_()` 3199~3246
- 분류: C. 성능 개선 대상
- 현재 역할: A1:J2의 관리 헤더를 출력한다.
- 문제 이유: 월간 헤더는 다수의 `getRange().setValue()` 호출, 연간 헤더도 여러 개의 독립 호출을 사용한다.
- 중복/의존: KPI 메타 K:R은 이미 `setValues()`로 배치 출력한다.
- 변경 영향: A1:J2의 표제·값 좌표는 대시보드/운영자가 참조할 수 있다.
- 권장 조치: 현재 좌표를 유지한 2차원 값 배열로 `setValues()`를 사용한다. 적용 전후 A1:J2 값 비교가 필요하다.
- 판단 확신도: 높음

### AS-06 — 연간 원본 연결을 위한 행 단위 push

- 파일/위치: `apps-script/Code.gs` 516~609
- 분류: C. 성능 개선 대상
- 현재 역할: 각 월의 복사값을 `allRows`에 합쳐 한 번에 쓴다.
- 문제 이유: `values.forEach(row => allRows.push(row))`가 행별 반복 복사를 한다.

- 변경 영향: 월 순서·빈 행 보존을 바꾸면 연간 원본 연결 결과가 달라질 수 있다.
- 권장 조치: 리팩터링 단계에서 안전한 배열 병합으로 단순화하되, 대량 배열 인자 한계를 고려한다.

### AS-07 — 월간/연간 MSY 메타 행 구성의 중복

- 현재 역할: 월간·연간 연동 탭에 같은 MSY 2행×8열을 쓴다.

## 3. Dashboard Audit

### DB-01 — L3 최신 유효일 별도 GViz 요청

- 파일/위치: `index.html` `readMonthlyMetadata()` 2865~3009, `loadPigsData()` 5435~5621
- 분류: D. 중복/불필요 의심 — 추가 검증 필요
- 현재 역할: 월간 상세, K:R 메타, L3 최신일, 연간 K:O 요약을 4개 병렬 요청한다.
- 문제 이유: L3는 K:R 메타에도 `최신 유효일` 값으로 포함되어 있다. 일반 성공 경로에서는 같은 월간 탭에 대한 별도 요청일 수 있다.
- 중복/의존: 과거 메타에서 최신일을 찾지 못한 연동 오류가 있었으므로, 분리 요청은 의도적 안정장치일 수 있다.
- 변경 영향: 단순 제거는 메타 파싱 오류를 최신일 오류로 바꿀 수 있다.
- 권장 조치: 메타에서 최신일을 우선 읽되 실패 시 L3 단일 조회를 하는 fallback이 기존 안정성을 유지하는지 실제 브라우저로 검증한다.
- 판단 확신도: 중간

### DB-02 — 고정 최대 범위의 상세 GViz 조회

- 파일/위치: `index.html` 상수 `MONTHLY_DATA_RANGE`, `loadPigsData()` 5476~5501
- 분류: D. 중복/불필요 의심 — 추가 검증 필요
- 현재 역할: 월간연동용 상세 A1:I1215를 항상 읽어 최신 날짜 블록을 찾는다.

- 변경 영향: 범위를 줄이면 더 긴 월 작업일지가 잘릴 수 있다.
- 권장 조치: Apps Script가 최신 복사 종료행을 메타로 이미 제공하므로, 범위 동적화의 이득과 GViz 호환성·오류 대응을 검증한 후에만 변경한다.
- 판단 확신도: 중간

### DB-03 — 인라인 이벤트와 전역 함수 혼용

- 파일/위치: `index.html` 863, 883, 903, 911, 1200, 1217, 4091; 5628~5676; 5723~5726
- 분류: F. 구조적 개선 후보

- 판단 확신도: 높음

### DB-04 — 데이터 계층별 역할 분리는 유지

- 파일/위치: `index.html` 4994~5350

## 6. 예상 리팩터링 효과

- 제거 가능한 코드: 확정 삭제 대상 0개.
- 통합 가능한 구성: 월간/연간 MSY 메타 행 생성 1개.
- 감소 가능한 Sheets API 호출: 현재 8개 원본 월 탭이 존재한다. 전체 갱신의 구조상 KPI 수집·최신월 탐색·연간 출력에서 같은 탭이 최대 3회 스캔된다. 스캔 1회당 `getValues`, `getDisplayValues`, `getFormulas` 3개 읽기를 수행하므로, 분석 결과를 공유하면 중복 스캔 16회, 데이터 읽기 호출 최대 48회를 줄일 여지가 있다. 이는 정적 코드 경로 기준이며 Apps Script 실행 로그 계측값은 아니다.
- 단순화 가능한 데이터 흐름: 날짜행 목록의 다음 원소를 블록 종료 판단에 재사용할 수 있고, 복사용 값은 분석 결과에서 재사용할 수 있다.
- 유지보수성: v11.0의 앵커 판정 규칙은 진단 함수로 노출되어 있어 유지가 필요하다. 이를 제거하지 않고 분석 결과 객체만 공통화하는 방식이 안전하다.

## 7. 감사 한계

1. GitHub 정본 v11.0과 현재 연동 탭 출력의 구조 일치는 확인했지만, 바운드 Apps Script 편집기의 실제 소스·설치 트리거 목록·실행 로그는 직접 읽지 못했다.
2. GitHub Pages 실제 브라우저 화면의 최신 연결 성공은 이번 감사에서 자동화해 재현하지 않았다.
3. AS-08, DB-01, DB-02는 실제 실행·브라우저 회귀 테스트 후에만 변경해야 한다.
