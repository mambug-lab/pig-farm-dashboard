# 양돈장 종합관리 프로그램 — 코드 정리·리팩터링 감사

- 감사일: 2026-09-07
- 범위: Google Apps Script, GitHub Pages `index.html`(HTML/JavaScript/CSS), Google Sheets 연동 구조
- 원칙: 운영 코드·시트·트리거·배포·GitHub는 수정하지 않았다.

## 1. Executive Summary

현재 시스템의 실제 데이터 흐름은 `월별 원본 작업일지 → Apps Script 집계/연동 탭 → GViz JSONP → index.html → DOM`이다. 현재 시트 출력(K:R KPI 메타와 연간 K:O 월별 집계)은 Drive의 `Code.gs v10.0` 백업과 일치한다. 그러나 GitHub의 `apps-script/Code.gs`는 이전 v7 구조로, 이 메타·집계 생성 로직이 없다. 따라서 GitHub의 GS 파일을 현 운영 Apps Script 정본으로 단정할 수 없다.

삭제가 확실한 운영 코드는 발견하지 못했다. Apps Script의 메뉴·트리거·수동 실행 함수는 코드 내부 참조가 적어도 외부 진입점이므로 dead code로 분류하지 않았다. 대시보드의 모든 선언 함수와 정적 DOM ID도 현재 참조가 확인된다.

가장 큰 개선 후보는 v10 전체 갱신의 반복 전수 스캔이다. `refreshDashboardLinks()`가 KPI 수집을 위해 월별 원본을 1회 스캔한 뒤, 월간 출력에서 최신 월 탐색을 위해 다시 스캔하고, 연간 출력에서 다시 스캔한다. 현재 존재하는 원본 탭 8개(5~12월) 기준, `scanMonthlySheet_()`는 최대 24회 실행되고 각 실행마다 `getValues()`, `getDisplayValues()`, `getFormulas()`를 호출한다. 즉 스캔 데이터 읽기만 코드 경로상 72회이며, 월·연간 복사용 추가 `getValues()`가 뒤따른다.

| 분류 | 건수 | 결론 |
| --- | ---: | --- |
| A. 확실히 삭제 가능 | 0 | 확인하지 못함 |
| B. 통합 가능 | 1 | MSY 메타 행 구성 중복 |
| C. 성능 개선 대상 | 5 | 반복 원본 스캔, 재읽기, 광범위 초기화, 소규모 반복 쓰기, 중간 배열 복사 |
| D. 추가 검증 필요 | 3 | GitHub/실행 GS 불일치, 이중 트리거, 최신일 별도 GViz 요청 |

| F. 구조적 개선 후보 | 2 | Apps Script 정본 관리, 대시보드 이벤트 방식 |

## 2. Apps Script Audit

### AS-01 — 같은 원본 월별 시트의 3중 전수 스캔

- 파일/위치: Drive `Code.gs v10.0`, 211~251, 558~626, 415~555, 630~675, 1388~1475
- 분류: C. 성능 개선 대상
- 현재 역할: 전체 갱신 시 유효일·KPI·MSY를 수집하고, 최신월 복사와 연간 복사를 만든다.
- 문제 이유: `collectAnnualDailyKpiRecords_()`가 모든 월을 분석한 뒤, `refreshMonthlyLinkSheetInternal_()`의 `findLatestMonthlySheetWithValidData_()`가 동일 월을 재분석하고, `refreshAnnualLinkSheetInternal_()`가 다시 재분석한다.
- 중복/의존: `analyzeMonthlySheet_()`가 반환하는 `scan`·`validBlocks`는 첫 수집에서 이미 확보되지만, 이후 두 출력 경로로 전달되지 않는다.
- 변경 영향: 분석 결과 캐시를 잘못 공유하면 최신 월 선택·유효일·MSY가 달라질 수 있다. 동일 실행 안에서만 불변 스냅샷을 공유해야 한다.
- 권장 조치: `refreshDashboardLinks()`에서 월별 `analyzeMonthlySheet_()` 결과를 한 번만 만들고, KPI 수집·최신월 선택·연간 복사에 같은 분석 결과를 전달한다. 월간/연간 단독 갱신도 공통 분석 컨텍스트 생성 함수를 사용한다.
- 확신도: 높음

### AS-02 — 이미 메모리에 있는 원본 값의 재조회

- 파일/위치: Drive `Code.gs v10.0`, 317~404, 415~555, 677~969, 3287~3315
- 분류: C. 성능 개선 대상
- 현재 역할: 분석 후 원본 A:I를 최신 유효일 끝까지 읽어 연동 탭에 복사한다.
- 문제 이유: `analyzeMonthlySheet_()`의 `scan.values`가 전체 A:I 값을 이미 보유하는데 `readMonthValuesUntilRow_()`가 같은 범위를 다시 `getValues()`로 읽는다.
- 중복/의존: AS-01과 결합된다. 월간 최신월 1회 및 유효 연간 각 월 1회가 추가 읽기다.
- 변경 영향: `scan.values.slice(0, copyEndRow)`로 대체할 때 행 수·열 수·값 형식이 현재 `getValues()` 결과와 동일한지 검증해야 한다.
- 권장 조치: 분석 결과의 `scan.values`를 복사용으로 재사용하되, 독립 실행의 기존 출력과 값·행 수를 비교하는 회귀 검증을 추가한다.
- 확신도: 높음

### AS-03 — 연간 메타 영역 전체 열 초기화

- 파일/위치: Drive `Code.gs v10.0`, 3360~3385; `refreshAnnualLinkSheetInternal_()` 415~455
- 분류: C. 성능 개선 대상
- 현재 역할: 이전 갱신의 KPI/월별 요약 잔존값을 막기 위해 K:R을 비운다.
- 문제 이유: 연간연동용 현재 그리드는 22,796행이므로 매 갱신마다 K:R 약 182,368개 셀을 `clearContent()`한다. 실제 메타·월별 요약은 상단 수십 행만 사용한다.
- 중복/의존: 잔존 행 제거라는 안전 목적은 필요하다. 단순히 초기화를 삭제하면 이전 연도의 남은 행이 보일 수 있다.
- 변경 영향: 초기화 범위를 너무 작게 잡으면 이전 월별 집계 행이 남는다.
- 권장 조치: 기존 집계의 마지막 사용행과 새 집계의 마지막 사용행 중 큰 범위까지만 초기화하거나, 관리된 K1:O 영역의 합리적 상한을 명시한다. 변경 전·후 잔존 데이터 테스트가 필요하다.
- 확신도: 높음

### AS-04 — 헤더의 셀 단위 반복 쓰기

- 파일/위치: Drive `Code.gs v10.0`, `writeMonthlyHeader_()` 2617~2753, `writeAnnualHeader_()` 2760~2802
- 분류: C. 성능 개선 대상
- 현재 역할: 연동 탭 상단 관리 정보를 작성한다.
- 문제 이유: 월간 헤더는 14회, 연간 헤더는 6회 `getRange().setValue()`를 수행한다. 인접 셀은 2차원 배열 한 번 또는 소수의 `setValues()`로 쓸 수 있다.
- 중복/의존: 메타 K:R 작성은 이미 `setValues()`를 사용한다.
- 변경 영향: 병합 셀·서식·값 배치가 달라지면 대시보드 참조 범위가 깨질 수 있다.
- 권장 조치: A1:J2의 값 배열을 명시하여 동일 좌표에 배치하고, 현 시트 A1:J2와 byte-equivalent 수준의 값 비교 후 적용한다.
- 확신도: 높음

### AS-05 — 연간 행의 반복 push

- 파일/위치: Drive `Code.gs v10.0`, 415~555
- 분류: C. 성능 개선 대상
- 현재 역할: 월별 원본 복사값을 `allRows`로 합친 뒤 한 번에 쓴다.
- 문제 이유: `values.forEach(...allRows.push(row))`는 대량 배열 참조를 한 행씩 복사한다.
- 중복/의존: Spreadsheet API 호출 수에는 큰 영향을 주지 않으며, AS-01/02가 우선이다.
- 변경 영향: 월 순서 또는 빈 행 보존이 바뀌면 연간 원본 연결 결과가 달라질 수 있다.
- 권장 조치: 우선순위는 낮다. 리팩터링 단계에서 `push(...values)` 또는 사전 크기 산정 방식으로 단순화하되 대용량 인자 한계 여부를 고려한다.
- 확신도: 중간

### AS-06 — 월간/연간 MSY 메타 행 생성 중복

- 파일/위치: Drive `Code.gs v10.0`, `writeMonthlyDashboardMetadata_()` 2251~2423, `writeAnnualMetadata_()` 2430~2610
- 분류: B. 통합 가능
- 현재 역할: 동일한 2행×8열 MSY 정보를 두 연동 탭에 작성한다.
- 문제 이유: 라벨·값 생성 규칙이 두 함수에 중복되어, MSY 항목을 수정할 때 한쪽만 변경될 위험이 있다.
- 중복/의존: 월간 K:R은 대시보드가 읽는다. 연간 K:R은 현재 HTML의 월별 집계 파서가 직접 사용하지 않지만 운영 확인용일 수 있다.
- 변경 영향: 연간 메타는 사람이 확인할 수 있으므로 삭제 대상이 아니다.
- 권장 조치: `buildMsyMetadataRows_(msy)` 같은 순수 헬퍼로 공통 행 배열을 만들고, 각 출력 함수는 자신에게 필요한 추가 행만 작성한다.
- 확신도: 높음

### AS-07 — onEdit와 onChange가 같은 전체 갱신을 호출

- 파일/위치: Drive `Code.gs v10.0`, `installDashboardTriggers()` 3507~3552
- 분류: D. 중복/불필요 의심 — 추가 검증 필요
- 현재 역할: 편집 및 변경 이벤트 때 연동 탭을 자동 갱신한다.
- 문제 이유: 한 사용자 편집에서 두 설치형 트리거가 모두 발생하면 전체 갱신이 중복 실행될 수 있다. 반대로 둘 중 하나를 제거하면 현재 의도한 변경 유형을 놓칠 수 있다.
- 중복/의존: 트리거 목록·실행 로그·실제 바운드 스크립트 상태는 이번 감사에서 직접 확인하지 못했다.
- 변경 영향: 잘못 제거하면 자동 갱신 누락, 유지하면 Apps Script 실행 시간·동시 실행 충돌 가능성이 있다.
- 권장 조치: Apps Script의 설치된 트리거와 실행 로그에서 같은 편집의 이중 실행 여부를 먼저 확인한다. 확인 전에는 변경하지 않는다.
- 확신도: 중간

### AS-08 — 메뉴·수동 실행·진단 함수는 유지

- 파일/위치: Drive `Code.gs v10.0`, `onOpen()` 140~184, `setupDashboardLinkedSheets()` 188~209, `showValidationAudit()` 2812~2872, `showCumulativeMsySummary()` 2874~2948
- 분류: E. 유지 필요
- 현재 역할: Spreadsheet 메뉴, 최초 설치, 유효일/MSY 진단 로그를 제공한다.
- 문제 이유: 코드 내부 참조가 하나뿐이거나 없더라도 메뉴 문자열과 수동 실행의 외부 진입점이다.
- 중복/의존: `onOpen`과 메뉴 항목 이름으로 연결된다.
- 변경 영향: 제거 시 운영자가 수동 갱신·진단을 수행할 수 없게 된다.
- 권장 조치: 유지한다. 필요 시 운영 매뉴얼에 외부 진입점임을 명시한다.
- 확신도: 높음

### AS-09 — GitHub v7과 Drive v10의 정본 불일치

- 파일/위치: GitHub `apps-script/Code.gs` 1~513 / Drive `Code.gs v10.0`
- 분류: F. 구조적 개선 후보
- 현재 역할: GitHub는 코드 관리 기준, Drive v10은 현재 출력 구조와 일치하는 발견 백업이다.
- 문제 이유: GitHub v7에는 v10의 고정 입력검사(13~16, +39), K:R KPI 메타, K:O 월별 요약, MSY 계산이 없다. 따라서 저장소 GS로는 현재 시트 출력을 재생성할 수 없다.
- 중복/의존: 현행 HTML은 v10이 생성하는 월간 K:R 및 연간 K:O를 직접 읽는다.
- 변경 영향: GitHub v7을 실행 GS에 덮어쓰면 대시보드 연동이 깨질 수 있다.
- 권장 조치: 별도 승인 단계에서 Apps Script 편집기의 실제 소스를 내보내고, 해시 대조 후에만 GitHub와 동기화한다. 이번 감사에서는 수정하지 않는다.
- 확신도: 높음

## 3. Dashboard Audit

### DB-01 — 최신 유효일의 별도 GViz 요청

- 파일/위치: `index.html`, 2750~2886, 5320~5387
- 분류: C. 성능 개선 대상 (D 검증 조건 포함)
- 현재 역할: 월간 상세 A1:I1215, 월간 메타 K1:R10, 최신일 L3, 연간 요약 K1:O30을 병렬 조회한다.
- 문제 이유: L3는 이미 K1:R10 안에 있고 `writeMonthlyDashboardMetadata_()`가 L3에 `최신 유효일`을 기록한다. 동일 갱신에 월간 시트로 2회가 아닌 3회 요청한다.
- 중복/의존: 분리 L3 요청은 과거 연동 오류 대응을 위해 유지됐을 가능성이 있다. 메타 범위의 GViz 형식/빈 셀 처리와 별도 단일 셀 조회의 신뢰성 차이는 실제 브라우저에서 재검증하지 못했다.
- 변경 영향: 단순 삭제 시 메타 파싱 실패가 최신일 오류로 바뀔 수 있다.
- 권장 조치: 메타에서 최신일을 우선 읽고, 실패할 때만 L3 단일 요청하는 fallback으로 통합할 수 있는지 회귀 테스트한다.
- 확신도: 중간

### DB-02 — 인라인 이벤트와 전역 함수 혼용

- 파일/위치: `index.html`, 816, 824, 1113, 1130, 3976 및 5513~5561, 5608
- 분류: F. 구조적 개선 후보
- 현재 역할: 상세 패널 열기/닫기, 새로고침, 트리 펼치기에 `onclick`을 사용하고 초기화에는 `addEventListener('load', ...)`를 사용한다.
- 문제 이유: 동적 HTML의 `toggleTreeGroup()`은 전역 함수여야 하며, 이벤트 등록 방식이 두 가지로 섞여 있다.
- 중복/의존: 중복 이벤트 리스너는 발견하지 못했다.
- 변경 영향: 이벤트 위임이나 `addEventListener`로 전환할 때 동적 트리의 클릭 동작·모바일 동작이 달라질 수 있다.
- 권장 조치: 기능 변경이 없는 별도 리팩터링에서 상단 정적 버튼과 동적 트리를 각각 명시적으로 등록한다. 이번에는 유지한다.
- 확신도: 높음

### DB-03 — DOM 상태·렌더링 로직은 유지

- 파일/위치: `index.html`, 1715~1847, 4879~5204, 5211~5263
- 분류: E. 유지 필요
- 현재 역할: 언어 변경 후 현재 조회 결과를 재렌더링하고, 상세 돈군/월별 요약/그래프를 서로 다른 DOM 영역에 렌더링한다.
- 문제 이유: 전역 상태가 많아 보이지만 언어 변경 시 재조회 없이 화면을 갱신하는 데 사용된다. 상세·월별·그래프는 입력 데이터와 출력 영역이 다르다.
- 중복/의존: 상단 KPI는 GS 메타, 돈군 상세는 최신일 상세행, 월별 현황은 연간 요약이라는 역할 분리가 확인된다.
- 변경 영향: 상태 제거 또는 렌더 통합 시 언어 전환·부분 오류 표시가 깨질 수 있다.
- 권장 조치: 유지한다.
- 확신도: 높음

### DB-04 — dead code·미사용 DOM·미사용 CSS

- 파일/위치: `index.html` 전체 (5,619행)
- 분류: A 해당 없음
- 현재 역할: 단일 파일 스타일·UI·데이터 조회·렌더링을 제공한다.
- 문제 이유: 정적 분석에서 선언 함수 51개와 주요 ID의 현재 참조를 확인했다. CSS의 동적 클래스는 JavaScript 템플릿으로 생성되므로 단순 CSS 검색만으로 삭제 판정을 하지 않았다.
- 중복/의존: `onclick` 연결 함수와 언어 재렌더링 함수도 사용처가 있다.
- 변경 영향: 없음.
- 권장 조치: 이번 단계에서 삭제하지 않는다. 향후 실제 브라우저 DOM 커버리지 검사 후에만 A 등급을 재판정한다.
- 확신도: 높음

## 6. 예상 리팩터링 효과

- 제거 가능한 코드: 이번 감사에서 확정 삭제 대상은 0개다.
- 통합 가능한 함수/구성: 월간·연간의 동일 MSY 2행×8열 구성 1개, 이벤트 처리 방식 1개 구조.
- 감소 가능한 Sheets API 호출: 현재 8개 원본 탭 기준 전체 갱신에서 월별 스캔 24회×3 읽기=72회가 확인된다. 분석 결과를 공유하면 같은 실행의 중복 16회 스캔(48회 읽기)을 없앨 여지가 있다. 이는 코드 경로 기준이며 Apps Script 실행 로그의 실제 RPC 계측값은 아니다.
- 감소 가능한 대시보드 요청: 최신일 L3를 메타 조회의 안전한 fallback으로 바꿀 수 있다면 일반 성공 경로에서 GViz 요청 1회를 줄일 수 있다.
- 단순화 가능한 데이터 흐름: 실제 실행 GS를 GitHub 정본으로 동기화하면, 운영·백업·저장소 사이의 버전 판정 위험이 줄어든다.
