## 2. 원본 A:I 열

| 열 | 원문/내용 | 사용 |
| --- | --- | --- |
| A | Отделение | 돈사·구역, 날짜행, ИТОГО/ВСЕГО 표시 |
| B | T min-max / влажность | 온도·습도 등 양식 정보 |
| C | 세부 돈군 | основное, свиноматок 등 세부 구분 |
| D | Предыдущий день | 전일재고 |
| E | Завоз / Приплод | 전입·분만 |
| F | Вывоз | 전출 |
| G | Отбор / погибшие | 현재 대시보드에서 폐사 지표로 집계 |
| H | Продажа | 판매·출하 |
| I | Текущий день | 금일재고 |

G열의 원문은 도태/선별 의미도 포함할 수 있으나 현재 프로그램 지표명은 ‘폐사’이다. 실제 현장 분류 정의를 새로 변경하지 않았다. B열과 일지 하단의 관리작업·사료/약품·교육란의 존재를 별도 앱 모듈 완료로 해석하지 않는다.

### 합계행

- `ИТОГО`는 부분합. 모돈수는 C열 `свиноматок` 등 모돈 구분이 붙은 ИТОГО의 I열을 사용한다.
- `ВСЕГО`는 농장 전체 총계. G=당일 폐사, H=당일 출하, I=총 사육두수.
- 부분합과 총계를 일반 돈사 행에 더하면 중복 집계되므로 역할을 구분한다.
- 초기 표준 일지의 Итого 합계 표시와 현재 데이터 시트의 ИТОГО/ВСЕГО 역할을 혼동하지 않는다.

## 3. 원본 좌표와 월간연동 좌표

Drive v10 및 현재 출력으로 확인한 규칙이다. GitHub GS는 다른 검사 규칙이므로 8절을 함께 읽는다.

| 구분 | 원본 | 월간연동용 |
| --- | --- | --- |
| 원본 복사 시작 | A1 | A3 |
| 첫 날짜행 | 1행 | 3행 |
| 첫 유효 입력 검사구간 | E13:H16 | 복사 후 E15:H18 |
| 두 번째 검사구간 | E52:H55 | 복사 후 E54:H57 |
| 세 번째 검사구간 | E91:H94 | 복사 후 E93:H96 |
| 반복 간격 | 39행 | 39행 |
| 8월 26일 날짜 블록 | 976~1014행 | 978~1016행 |
| 8월 26일 검사구간 | E988:H991 | E990:H993 |

월간연동용에 +2행이 생기는 것은 위쪽 1~2행 관리정보 때문이다. **원본 E15:H18과 원본 E13:H16은 같은 범위가 아니다.**

현재 월간 복사는 원본 A1:I1014 → 월간 A3:I1016이다. 원본 8월 27일 날짜행 1015는 복사 범위 밖이다. 연간은 각 월의 원본 1행~해당 월 최신 유효일 끝을 연결하므로 원본 좌표에 항상 +2만 적용하여 연간 위치를 계산하면 안 된다.

## 4. 유효일과 복사 규칙

1. 원본 월별 시트에서만 검사한다.
2. `13 + 39×n`행부터 4행, E:H의 수식이 아닌 수동 숫자 입력 여부를 검사한다.
3. Drive v10은 수동 숫자 0도 인정하고 수식 결과 0은 제외한다.
4. 유효 검사구간에 대응하는 날짜행을 찾고 다음 날짜행 직전까지 전체 블록을 유지한다.
5. 월간은 원본 1행부터 마지막 유효일 끝까지 복사한다. 중간 무효일을 제거하여 압축하는 방식이 아니다.
6. KPI 및 MSY는 별도로 선별한 유효일 기록에서 집계한다. 따라서 복사된 연간/월간 원본행 전부를 재합산하는 방식과 구분해야 한다.
7. HTML은 GS가 확정한 날짜 및 요약을 사용한다. 직접 E:H를 검사하지 않는다.

현재 집계 제외일은 6월 28일, 7월 17일, 7월 30일이다. 지정 4행 E:H는 비어 있지만 전체 일지가 공란이라는 뜻은 아니다. 이번 115개 유효일에는 모두 0이 아닌 수동 숫자도 있어 수동 0 인정 정책의 실제 런타임 적용 여부는 데이터만으로 구별되지 않는다.

전송 방식은 Google Visualization(GViz)의 JSONP. 위 범위는 정본 HTML 상수에서 확인했다. 현재 월간 그리드는 1032행이지만 코드 요청은 1215행이다. 이번에는 Sheets API로 실제 데이터를 읽었으며 해당 GViz 요청의 브라우저 실행 성공까지 검증한 것은 아니다.

상단 ‘마지막 업데이트’는 HTML 조회 시각이고 ‘작업일지 기준일’은 L3의 데이터 날짜이다. 소스에는 초기 페이지 로드 및 새로고침 버튼 조회가 있으며 반복 타이머 기반 자동 폴링은 확인되지 않는다.

## 8. GitHub GS와의 차이

| 항목 | GitHub Code.gs | Drive v10 / 현재 출력 |
| --- | --- | --- |
| 유효 입력 구간 | 날짜 블록 전체 E:H, ИТОГО/ВСЕГО 제외 | 원본 E13:H16,+39행 |
| 수동 0 | 제외 | 백업 코드상 인정 |
| 월간 관리정보 | A1:J2의 이전 구조 | F2/H2 유효일·주기 포함 |
| KPI 메타 생성 | K:R 생성 로직 없음 | K:R 생성 및 현재 값 존재 |
| 연간 월별 요약 | K:O 생성 로직 없음 | K5:O 이하 요약 생성 및 현재 값 존재 |
| MSY 계산 | 해당 요약 함수 없음 | 원본 유효일 기록 및 달력일수 기반 |

현재 출력은 v10과 일치하나 실행 GS 원본을 직접 읽지 못했으므로 완전한 코드 동일성은 미확인이다. GitHub 코드만으로 현재 메타를 재생성할 수 있다고 가정하지 않는다.

## 9. 확인 절차 및 변경 경계

- 이 문서 갱신 시 원본 값·수식과 KPI 메타를 함께 읽는다.
- 최신 유효일, 복사 끝, 월 유효일, 월별 출하·폐사, 모돈 평균과 MSY 기간을 대조한다.
- 자동 갱신 정상 여부는 트리거 목록·실행 로그와 실제 입력 후 갱신으로 별도 판단한다.
- 관리 검토 중에는 원본이나 연동 탭에 값을 써 넣지 않는다.
